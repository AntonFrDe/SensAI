Les limites du projet

Ce qui ne marche pas encore assez bien

Un juge peu fiable

Sur les débriefs, le juge llama3.2:3b voit 6 faits sur 111, quand le code en retrouve 74 sur 81.

30 questions encore ratées

57 sur 87 : abattages, probabilités et calculs restent fragiles pour un modèle de 4B.

La lenteur sur CPU

Environ 5 tokens par seconde sur nos machines : une explication complète prend plusieurs dizaines de secondes.

Un usage local, mono-joueur

Pas d’authentification, choix du modèle gardé en mémoire, cartes adverses mal lues dans une question libre.

[ANTON] Soyons honnêtes sur les limites. Un : notre juge automatique n’est pas fiable. Sur les débriefs, le juge llama trouve 6 faits sur 111, alors qu’une simple vérification par le code en retrouve 74 sur 81. Les scores du juge sont donc indicatifs. Deux : 30 questions sur 87 restent ratées, surtout les abattages et les probabilités. Trois : sur CPU, le modèle produit environ 5 tokens par seconde, une explication complète prend donc du temps. Quatre : c’est une application locale pour un joueur, sans authentification, et le lecteur de situations prend encore les cartes de l’adversaire pour celles du tableau. Nikita et Amine vont vous dire comment on compte y remédier.
